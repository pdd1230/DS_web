# DeepSight PDCA 개선 구현 및 검토 결과 (2026-11-05)

## 1. 승인·기준선

대화에서 개선 계획이 승인되어 Do(개선 구현)를 수행함. 사용자에게서 전달받은 기존 실제 실행 로그:

- 처리 이미지: 20장 / 정상 종료
- 기준선 이미지별 얼굴 **개수 완전 일치**: 14/20 = **70%**
- 과검출 이미지: 4장 / 미검출 이미지: 2장 / 최종 검출 박스: 29개
- `img_012`: YOLO 1개, Haar 4개 → 통합 3개. Haar의 추가 오검출 2개 확인.
- `run.bat`는 사용자가 이미 삭제 완료. 이번 변경에도 재생성하지 않음.

## 2. 추가 입력 자료 반영

- 2026-11-05 사용자가 새로 제공한 `requirements(20261105-041137).txt`는 **38개 패키지 고정 버전 목록**임.
- 내용은 기존 프로젝트 목록과 동일함. 원본은 UTF-16 LE, 새 `requirements.txt`는 UTF-8(BOM 없음).
- 예시: `numpy==2.4.6`, `opencv-python==4.14.0.94`, `ultralytics==8.4.202`, `torch==2.15.0`.
- 실제 사용자 PC 환경의 `pip install -r requirements.txt`, `pip check`는 수행하지 않음.

## 3. 개선 구현

- `source/main_1.py`: 4개 검출 정책 실험 가능(`legacy`, `yolo_only`, `haar_only`, `improved`).
- 검출 후보 이력 `detection_details.csv`와 처리 상태 `processing_status.csv` 추가.
- 모델별 신뢰도: YOLO의 confidence만 기록; Haar는 빈 값.
- 실패 이미지를 0개 얼굴로 처리하지 않고 평가에서 제외하며 상태 명시.
- 이미지 20장 및 개수 정답표 그대로 사용; 기존 CSV 컬럼은 보존.
- 실험 결과 폴더 분리(`outputs/experiments/`).

## 4. 구현 검증 — 이번 환경에서 실제 수행

| 시험 | 결과 | 근거 |
|---|---|---|
| Python 문법 컴파일 | 통과 | `python -m py_compile source/main_1.py` |
| 단위 테스트 | **6/6 통과** | `python -m pytest tests -q` |
| 기존 `img_012` 박스로 정책 검증 | 통과 | 기존 3개 유지(legacy), 개선안 1개+Haar 2개 보류(improved) |
| 처리 실패 분모 제외 | 통과 | `read_failed`를 `Not Evaluated`로 구분하는 테스트 |
| 실제 Haar 20장 처리 | **20/20장 정상 처리** | OpenCV Haar 검출 + 이미지/CSV 저장 |
| Haar 단독 개수 일치율 | **11/20 = 55%** | 해당 작업 환경, 현재 입력 사진·정답표 기준 |
| 최신 패키지 목록 인코딩 | 완료 | UTF-16 LE → UTF-8; 38개 버전 유지 |
| 실제 YOLO 추론·4정책 성능 | **미실행** | 이번 작업 환경에 `ultralytics` 패키지 없음 |

**주의:** 55%는 이번 환경에서 재실행한 Haar 단독 결과로, 70%는 사용자가 제공한 Windows 혼합모델 실행 로그임. 서로 다른 실행 환경·방식이므로 완벽히 통제된 비교는 아님. 4정책 동시 비교의 결과를 확정하기 전 참고용으로만 사용.

## 5. 잔여 리스크 및 Check 단계 필요 작업

1. 사용자 Windows PC에서 `python source\\main_1.py --compare` 실행 및 CSV 확인.
2. 4정책의 개수 일치율, 과검출, 미검출, 특히 `img_007/008/011/012/017/020` 비교.
3. `improved`가 실제 얼굴을 누락시키는지, 보류된 Haar 후보를 이미지별 수동 검수.
4. `img_019`, `img_020`처럼 YOLO=0인 경우 Haar의 보완 성능 점검.
5. 얼굴 위치별 정답 박스 라벨링 후 TP/FP/FN, Precision/Recall 산출.
6. 패딩/블록 크기 조절 전 실제 모자이크 비식별화 수준 시각 평가.
7. Windows 가상환경에서 패키지 설치·호환성·실제 모델 실행 및 산출물 확인.

## 6. 결론

Do 단계의 **소스 개선 및 자동 테스트는 완료**했으나, 실제 YOLO 추론 없이 성능 향상은 확정할 수 없음. `legacy`를 기본으로 유지하고 `improved`는 안전성 검증이 필요한 실험 방식으로 분류함. Check 단계의 최종 성능 승인은 Windows에서 4정책 비교 및 시각 검수 이후 판단.
