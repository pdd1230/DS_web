# PDCA 구현 결과와 검증 구분

작성일: 2026-11-07. 사용자가 현재 계획서를 기준으로 전체 프로젝트 코드 작성을 요청하여 구현을 진행했다. ‘전체 PDCA가 끝난 상태’를 목표로 기능과 운영 산출물을 작성하되, 실제로 수행하지 않은 실환경 검증을 통과로 기록하지 않았다.

|단계|산출물|상태|
|---|---|---|
|P|원본 진단·승인 기준 계획·실행 기능 구체화|완료|
|D|Spring Boot·Python·데이터셋·DB 저장/조회·프로그램 실행·검수·보고서·이력|소스 구현 완료|
|C|Python 계약/기존 테스트·실제 추론·CLI 회귀·Spring HTTP 통합 시험|Linux H2·실제 MySQL8.4.11에서 수행; 세부 결과는 VALIDATION.md|
|A|의존성·버전 고정, Wrapper, 통합 시작/종료, 점검, 백업 도구, 설계/사용/운영 문서|산출물 제공; Windows·MySQL 운영 복원은 사용자 환경 확인 필요|

## 구현한 업무 흐름

1. 기준 사진 등록 또는 새 사진·정답 CSV 업로드.
2. 사진·정답 일관성 검증, 확정 데이터셋 버전 저장.
3. 초기·기준·4정책 프로그램 선택, 목적·보존 설명·허용 설정 입력.
4. 이전 보고서 매니페스트·해시 확인, 새 입력 스냅샷 생성.
5. 비동기 순차 실행, 단계·진행률·실행 로그 조회.
6. 결과 검증 후 DB 트랜잭션 수집, 정상 완료 게시.
7. 사진·정책·오답·처리 실패·미검수 기준 조회.
8. 원본/모자이크 확대, 검출 후보·좌표 조회.
9. 수동 검수 DB 저장, 추론 없이 분석만 재실행.
10. 새 보고서 개정 보관, 이전 개정·CSV·이미지·ZIP 다운로드.
11. 이전 실험 복제, 새 실험 ID로 재실행.
12. 과거 출력의 출처·미확인 설정 구분, CLI 백업 목록과 무결성 검증 다운로드.

## 의도적으로 남긴 범위

- 웹캠·동영상·비전 에이전트·새 모델은 승인 계획상 별도 확장이다.
- 실제 Windows MySQL 계정 비밀번호를 프로젝트에 임의로 넣지 않았다. config.ps1에서 입력한다.
- 화면은 목업 데이터를 사용하지 않는다. 실행 전에는 빈 목록과 안내를, 실행 후에는 DB 결과를 표시한다.
- H2 통합시험과 별도 MySQL8.4.11 운영 JAR 검증을 구분해 기록한다. Windows 실검증으로 확대하지 않는다.
- 기존 CLI 백업의 당시 입력·설정이 불명확하면 자동으로 새 성능 실험에 합치지 않는다. 원본 다운로드로 제공한다.
